Design principles #

These constraints shape every public type. Read them once; they explain the rest of the API.

PrincipleWhat it means for you
Tree in RustCanonical structure, watch, walk, and search live natively. JS owns expansion, selection, scroll.
Snapshot readsAll sync reads go through an immutable MirrorSnapshot, safe during React render. The port client hands back the same snapshot object until the next change.
Flat over nestedRows and entries cross NAPI as flat records. Virtualizers never walk a nested object tree.
Stable EntryIdSession-scoped ids stay stable across renames/moves. Capped at 2^53-1 for JS safety.
Typed errorsExpected FS failures throw FileSystemError with POSIX-like codes — use try/catch, not Result unions.
Version channelstreeVersion and decorationVersion bump independently so SCM churn does not thrash row caches.

Core types #

Shared identifiers and records used across engine and UI.

EntryId type #

type EntryId = number

Monotonic id assigned in Rust. Stable across renames and moves within a session. Reassigned on process boot. Safe as a React key, Map key, or JSON value.

FileSystemError class #

class FileSystemError extends Error

Expected filesystem failures. Check with isFileSystemError(e).

MemberTypeNotes
codeErrorCodeEACCES, ENOENT, EEXIST, EISDIR, ENOTDIR, ELOOP, ENOSPC, EROFS, EBUSY, EINVAL, ECANCELED, EFBIG (a payload over the remote transport’s per-request limit), EUNSUPPORTED, EUNKNOWN, ETIMEDOUT (a native read stalled), EDATALESS (cloud-evicted folder, not downloaded)
path?stringPath involved in the failure
ts
try {
  await fx.rename(id, 'new-name');
} catch (e) {
  if (isFileSystemError(e) && e.code === 'EEXIST') {
    // handle collision
  } else throw e;
}

Construct, populate, snapshot, mutate. Construction never walks the filesystem.

FieldTypeDefault / notes

respectIgnore?booleantrue — parse .gitignore / .ignore / .rgignore
followSymlinks?boolean | 'smart'Default 'smart' walks each canonical directory once per traversal, preferring ordinary paths. false skips linked subtrees. true follows aliases and cuts ancestor cycles.

FileExplorer class #

new FileExplorer(options: ExplorerOptions)

Read path: getSnapshot() → sync queries on the snapshot.
Write path: methods on the explorer (create, rename, …).
Subscribe: on('change', …).

FileExplorer runs where the native module loads: the utility process (through createFileExplorerHost) or plain Node. It cannot be constructed in an Electron renderer. A window uses a PortFileExplorer.

getSnapshot(): MirrorSnapshot
The current immutable snapshot. This class returns a new wrapper on every call, so compare treeVersion and decorationVersion, not the object.
populateFromRoots(): Promise<number>
Parallel walk of configured roots. Returns total entry count. Call once after construction for full load.
writeSnapshot(path): Promise<void>
Atomically save the current index for a later explorer using snapshotPath.
setExpanded(diff: { add?: EntryId[]; remove?: EntryId[] }): void
A no-op on this class, kept so both classes have the same shape. On a PortFileExplorer it updates the session’s expansion, and the host may walk newly expanded folders.
setViewport(opts: { offset; limit; overscan? }): void
Also a no-op on this class. On a PortFileExplorer it declares the visible window, so the host can send those rows first.
list(parentId, options?): Promise<ListPage>
Async paginated children. Prefer snapshot for already-loaded data.
prefetch(id, options?): Promise<void>
Warm children without adding to the expansion set.
create / rename / move / delete / copy
Structural mutations. Reject with FileSystemError on expected failures.
readFile / readText / writeFile / readFileStream
I/O by EntryId. Stream is AsyncIterable<Uint8Array>.
search(query, options?): readonly SearchHit[]
Fuzzy filename search over the in-memory tree (nucleo). Synchronous on this class; see search.
on(event, listener): Disposable
Events: change, change:tree, change:decorations, event, batch, warning, error. The ready event fires once after the first full population or root seeding. Late listeners receive it asynchronously.
registerDecorationProvider(provider): Disposable
SCM / lint / problems overlay. Reads via snapshot.getDecorations(id).
dispose(): Promise<void>
Stop watcher threads, release native resources. Idempotent.

MirrorSnapshot class #

An immutable view at one tree version and one decoration version. Never mutate it. A PortFileExplorer returns the same object until the next change, so === tells you whether anything moved.

readonly treeVersion: number
Structural version.
readonly decorationVersion: number
Decoration channel version.
roots(): readonly Entry[]
Workspace roots in display order.
visibleRows(options): readonly VisibleRow[]
Flat slice for virtualizers: expanded set + offset/limit. Cache-miss rows may set pending: true.
visibleRowCount(expanded, includeIgnored?): VisibleRowCount
known count plus pendingExpansions for incomplete folders.
getById / directChildCount / hasChildren / getDecorations
Point queries for rows and overlays.
ts
const rows = snap.visibleRows({
  expanded,
  offset: 0,
  limit: 100,
  includeIgnored: false,
});

ChangeNotice interface #

What a tree-driven 'change' or 'change:tree' listener receives on a FileExplorer. A decoration bump delivers the changed ids as readonly EntryId[]. A PortFileExplorer’s 'change' listener receives no argument: read getSnapshot() again. It is a pull model: the version bumps, and you re-read only the rows you need.

FieldTypeNotes
treeVersionnumber
decorationVersionnumber
treeChangedbooleanThe tree moved
decorationsChangedbooleanDecorations moved
changedIdsEntryId[]Entries that may have changed
childSetChangedEntryId[]Parents whose children changed
decorationChangedIdsEntryId[]Decoration-only updates
coarseSubtreesEntryId[]Watcher overflow regions

Host and port client #

How it runs in Electron: the engine in a utility process, and each window on a PortFileExplorer.

createFileExplorerHost function #

function createFileExplorerHost(options: ExplorerOptions): Promise<FileExplorerHost>

The utility-process factory. It loads the native module and owns the entry store, the walker and the watcher. Import it from @vibecook/mille/host.

FileExplorerHost interface #

Each port is an independent session (expansion, viewport and known ids). Electron’s MessagePortMain needs a short adapter first; the embedding guide has it.
readonly sessionCount: number
Attached client sessions.

In-process access for host-side SCM/indexers. Prefer host.registerDecorationProvider when badges must fan out to port clients.

Host-level decorations store shared by every session.

connectFileExplorer function #

function connectFileExplorer(port: MessagePortLike, options?: ClientOptions): Promise<PortFileExplorer>

The renderer-side factory. Import it from @vibecook/mille/port. Reads come from a local mirror of the rows in view; writes round-trip to the host over the wire protocol (v1 frames).

PortFileExplorer class #

What a window holds. It mirrors most of FileExplorer, with these differences:

  • list, prefetch, populateFromRoots and readFileStream are host-side only.
  • canUndo, peekUndo, lastMutation and cancelOperation are async, and capabilities() is an async method.
  • on supports change and warning only. Use onConnection() for the connection’s state, and ready() to wait for the first rows.
  • search is async and resolves hits that also carry their path.

ClientOptions interface #

FieldTypeDefault
prefetchRows?number100. Tune it to your virtualizer’s overscan.
mirrorCap?number4096. Cold expansions are evicted least recently used first.

search method #

FileExplorer search(query: string, options?: SearchOptions): readonly SearchHit[] PortFileExplorer search(query: string, options?: SearchOptions): Promise<PortSearchResults>

A fuzzy match over file names and paths in the in-memory entry list. Over a port each hit also carries its path, the result has clipped and treeVersion, and the options accept a signal. Searching file contents is out of scope for this package.

SearchOptionsTypeDefault
limit?numberOver a port: 100, at most 1000. On a FileExplorer: no limit unless you set one.
includeIgnored?boolean
kinds?number[]EntryKind values
caseSensitive?boolean

SearchHit: { entry, score, matchedIndices } — indices into the name for highlighting.

The React tree: @vibecook/mille-ui #

The engine owns structure; this package draws it. Its peers are React 19 and @tanstack/react-virtual. The Radix peers are optional, for the styled entry.
